# Registro de evidência

Copiar este molde para cada execução. Deixar o arquivo vazio até haver uma execução real. Não preencher resultado com o esperado local. Não inventar SHA: este diretório ainda não é um repositório git.

## Molde

- Caso:
- Camada: visualização no navegador, execução no Message Center, ou renderização em cliente de email.
- Versões: Node, Handlebars, `@react-email/components`, Tailwind, identificador do perfil, estado `homologation` do manifesto.
- Ambiente: sistema, e para cliente de email o nome e a versão. Separar Outlook na web de Outlook clássico no Windows.
- Data:
- Resultado esperado:
- Resultado observado:
- Evidência disponível: caminho do recorte ou captura, sem credencial e sem payload real de cliente.

## Promoção de estado

Uma capacidade só passa a `verified` para o comportamento que o registro mostra no destino. `formatCurrency` no par `20000` para `200,00` não cobre outro número. `eq` com literal continua `experimental` até o Message Center aceitar a seleção e o documento único. Linux, macOS e qualquer Node diferente de `24.21.0` continuam pendentes até um log dessa execução.

Visualização no navegador, execução no Message Center e renderização em cliente real são registros separados. Um não preenche o outro.

## Divergência

Registrar caso, trecho esperado, trecho observado e camada. Não alterar o merge, o helper nem o perfil para fazer o caso passar. Se o destino recusar a fonte combinada, o registro descreve a recusa e as variantes `per-locale` continuam sendo a alternativa explícita.
