# Locale with eq, alias, and fallback

Capability: `eq` with literal. Current state: `experimental`. The reference VTEX documentation compares two paths. The literal in the selector is a local simulator until Message Center. The template DSL does not emit `eq`; the compiler merge emits it.

## Minimal template

It is not a component. It is the variant combination. In [examples/basic-store/emails/order-confirmed.email.tsx](../../../examples/basic-store/emails/order-confirmed.email.tsx):

```ts
i18n: {
  localePath: 'orders.0.clientPreferencesData.locale',
  output: 'merged',
  aliases: { 'pt-br': 'pt-BR' },
}
```

The project test, on the same Node `24.21.0` on 2026-10-02, checks the combined artifact for the literals `"en-US"` and `"pt-br"`, and the presence of `{{#eq `. The `per-locale` output of `auth-code` does not contain `eq`.

The emitted order, read from `examples/basic-store/dist/order-confirmed.html` generated by that build, is: `en-US` branch, then `pt-br` branch with the `pt-BR` document, then the final `else` with the same `pt-BR` document.

## Synthetic JSON

Three payloads already used by the example, plus a fourth only for the alias. All synthetic.

- `en-US`: [examples/basic-store/fixtures/order-confirmed/delivery.json](../../../examples/basic-store/fixtures/order-confirmed/delivery.json). The local preview contains `Hello,` and the payload locale is `en-US`.
- Missing: [missing-locale.json](../../../examples/basic-store/fixtures/order-confirmed/missing-locale.json). The local preview contains `Olá,`.
- Unknown `fr-FR`: [unknown-locale.json](../../../examples/basic-store/fixtures/order-confirmed/unknown-locale.json). The local preview contains `Olá,` and does not contain `Hello,`.
- Alias: the same delivery object, with `orders.0.clientPreferencesData.locale` equal to `pt-br`. The automated test checks the literal in the artifact. Local selection of that alias follows the emitted branch: the `pt-BR` document, because the `eq` simulator compares with strict equality.

The full proof, with other catalogs, also saw `fr-FR` and missing locale fall to `Pedido confirmado`, without `Order confirmed`.

## Expected local result

- `en-US` resolves the English document
- `pt-br`, missing, and `fr-FR` resolve the Portuguese document
- forcing locale in preview alters the copy, not the fixture file
- the manifest remains `homologation: experimental` and emits `TARGET001` for `eq`

## Message Center

Follow [the manual procedure](../message-center.md) four times. Check the language of the resolved document, including the lowercase `pt-br` branch.

## Evidence

Four excerpts, one per payload, in the [record.md](../record.md) template. Layer: Message Center. The local preview does not fill these records.

## Approval

Each payload in its own record. Accepting `en-US` does not accept the alias or the fallback. `eq` with a literal only leaves `experimental` if the four behaviors, and the single document of the next case, are accepted on the target. Until then it remains `experimental`.

## Divergence

Record the locale sent and the language that came out. Do not normalize the alias only in preview, and do not silently swap the selector.
